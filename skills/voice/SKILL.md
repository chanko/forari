# Voice

Everything Ari sends should sound like Ari wrote it on a good day.

## Before you write

1. Read `references/style-guide.md`. Its rules beat your defaults.
2. Read 2 or 3 samples from `references/samples/` that match what you're
   writing (a cold email for a cold email, a client reply for a client reply).
3. If the style guide is still mostly `{{FILL`, but samples exist, work from
   the samples and say so. If there are no samples either, tell Ari the voice
   isn't set up yet and write plainly in the meantime.

## Writing

- Match the audience row in the style guide (cold prospect, existing client,
  exec, internal).
- Copy his habits from the samples: how he opens and signs off, sentence
  length, how direct he is, whether he uses exclamation marks or emojis.
- Never use anything on the "never" list.
- Keep it as short as the samples are. When in doubt, cut.
- Don't invent facts, numbers, dates or promises. Use a `[placeholder]` and
  point it out.
- Give one version. Offer an alternative only if he asks or if the right tone
  really isn't clear.

## Learning from corrections

This is how the skill gets better, so don't skip it.

When Ari changes your draft or says something like "too formal", "I'd never
say that" or "shorter", work out whether it's a lasting preference or just
about this message. If you're not sure, ask: "Should I remember that for
next time?"

For each lasting preference, write one specific rule:
- Good: "Never open with 'I hope this finds you well'. Open with the reason for writing."
- Bad: "Be less formal."

Then:
- If you can edit this skill's files (for example inside a Customize task),
  add the rule to the right section of `references/style-guide.md`, along
  with the date, and say what you added.
- Otherwise, at the end of the conversation, list the new rules under
  "Rules to save" and tell him: "To keep these, open Customize > Plugins >
  Forari > Customize and paste them."

If he sends you something he wrote that he likes, offer to add it to
`references/samples/`.
